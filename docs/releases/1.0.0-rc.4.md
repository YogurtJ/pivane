# Pivane 1.0.0-rc.4 · Pi 0.86.0 适配

本候选版将 Pivane 与 Pi Coding Agent 及配套官方依赖统一绑定到 **0.86.0**。RC3 及更早版本的发布资产保持不变；本说明和 Release 附件中的 SHA256 只适用于 RC4 的精确归档。

## 本版变化

- 适配 Pi 0.86 的原生 `role: system` transcript 消息。系统提示词与工具检查点保留在 Pi 原生会话中，但不会显示成网页聊天气泡、侧聊历史或公开 RPC 的普通消息。
- 会话上下文、会话迁移、HTML/JSONL 导出从实际 worker 的当前 system message 读取提示词；导入校验接受 Pi 0.86 的 system message、工具增量和 compaction system checkpoint，同时继续拒绝未知/畸形记录。
- 保留 Pi 0.86 的 TranscriptContext、离线模型目录、compaction 预算、缓存保活与诊断行为；Pivane 不自动选择未配置模型或执行未授权请求。
- 标题生成、辅助模型、侧聊、历史、compaction 与会话恢复流程按 Pi 0.86 的消息数量和状态流更新。
- 测试运行器隔离机器上的 Provider 环境变量，避免本机凭据污染离线目录和合成服务。

## 版本与安装

- 应用版本：`1.0.0-rc.4`
- Pi Coding Agent 及配套依赖：`0.86.0`
- 推荐 Node：`22.x`；本次 Linux ARM64 隔离验收使用 Node `22.23.2`
- 安装：下载 `pivane-1.0.0-rc.4.tar.gz` 与同名 `.sha256`，先核对 SHA256，再在独立版本目录执行 `npm ci` 和 `npm start`。
- 已有安装升级前：结束任务、暂停预约、保存草稿与附件，停止同一 Pi 身份的外部写入进程，完成数据备份后再切换代码目录；不要让新旧服务同时写同一 JSONL 会话。

## 验证范围

RC4 的最终验证结果必须使用 Release 附件 `1.0.0-rc.4.validation.json`，并核对其中的 `artifactSha256` 与归档 `.sha256` 完全一致。当前工作区已完成以下开发验证：

- `npm test`：232 项通过
- `npm run check`、`npm run check:docs`：通过
- `npm audit --omit=dev`：0 vulnerabilities
- Pi 0.86 RPC、compaction、标题、侧聊、会话迁移和桌面/手机 Chromium 专项：通过
- 发行包隔离验收：必须在 RC4 最终包修复会话导入的 Pi 0.86 system message 兼容后重新执行；失败的中间候选不作为 RC4 验收结论

没有在 RC4 包上重跑的平台或供应商不应被描述为 RC4 实机验收。浏览器手机宽度不等于原生手机/Safari 验收；真实供应商、付费媒体生成、第三方扩展和外部 CLI 身份仍需用户按自身配置单独核对。

## 回滚与兼容

Pi 原生会话仍是唯一事实来源，导入会创建新的 session identity，不覆盖原会话或启动 worker。更新失败或结果不确定时不自动重放；保留旧 release、备份与原有 `PI_*`、`pi5-*` 存储键，按[安装与恢复](../INSTALL_RECOVERY.md)执行离线核对和回滚。RC4 不会修改 RC1、RC2 或 RC3 的标签、归档或用户数据。

## English summary

Pivane **1.0.0-rc.4** pins the application and the Pi Coding Agent family to **0.86.0**. It adapts native `role: system` transcript checkpoints, preserves the effective system prompt through session context and HTML/JSONL transfer, and validates Pi 0.86 system/tool increments during import. RC3 and earlier artifacts remain unchanged.

Use the exact RC4 archive and checksum, Node 22.x, an isolated `npm ci`, and the attached validation JSON. The final RC4 acceptance record must bind every result to the archive SHA256; an intermediate failed candidate is not a release validation result. Unverified platforms, real providers, paid media operations and third-party extensions remain outside this candidate's certified scope.
