# Pivane 1.1.0 · 发布候选

本版基于 **Pi Coding Agent 0.87.1**，推荐 **Node.js 22.x（至少 22.19）**。当前为发布准备中的候选；公开下载以 [GitHub Releases](https://github.com/YogurtJ/pivane/releases) 为准。本地验收、实例升级与公开发布是不同状态，1.0.0 的原归档保持不变。

## 本版变化

- **项目文件浏览**：右侧文件区提供目录树、文件名/相对路径搜索、隐藏文件开关、路径面包屑与定位。项目文件和本轮修改共用只读查看器；宽屏并排查看，手机切换目录与正文，浏览不会自动调用模型。
- **任务进度卡**：内置 `update_plan` 工具，展示 Agent 报告的步骤、状态与说明。计划保存在原生会话，随刷新、重开、分叉和历史导航恢复；停止或回复结束不会自行标记步骤完成。
- **模型选择与跨设备收藏**：模型面板支持目录搜索、常用和最近使用，按供应商/模型 ID 区分同名型号。常用由同一实例跨设备保存，最近使用仍在当前浏览器；旧收藏经确认回执合并，兼容局域网 HTTP。
- **手机布局与焦点**：手机顶部保留项目入口，状态条显示线程名称；模型、思考与上下文集中于底部面板。输入区上下文圆环和聚焦摘要减少常驻占用，模型选择器不再自动唤起手机键盘。文件、历史与阅读模式从详情页进入。
- **操作与设置反馈**：分叉、历史重试、预约、模板、资源重载和队列操作增加等待反馈与重复提交保护；较早响应不会覆盖较新的视图。重进模型设置时刷新本地目录，保留辅助模型草稿。
- **更新提醒**：前后版本对比、清晰的更新入口和可重复打开的预览；预览不安装、不改写提醒状态。导航折叠按钮同步细化。
- **Pi 0.87.1 兼容**：同步固定整套 Pi 依赖；导入与早期分叉保留原生上下文编辑、用量和无保留压缩记录。主聊天保留原文，模型和完整上下文侧聊遵循编辑投影；升级探针覆盖这些差异。

完整行为与限制见 [CHANGELOG](../../CHANGELOG.md)、[用户指南](../USER_GUIDE.md)、[模型设置](../PROVIDER_SETTINGS.md)、[文件浏览](../FILE_VIEWER.md)及[版本与更新](../UPDATES.md)。

## 从 1.0.0 升级

使用包含 Pivane 代码和 Pi 0.87.1 锁定依赖的完整候选；只在旧应用中升级 Pi 不会加入本版兼容修复。正式发布后，支持应用受管更新的实例可从“设置 → 版本与更新”安装；发布前的本地候选按维护流程切换。

升级前保存草稿和临时对话、结束任务与 Shell、暂停预约，并停止使用同一身份的外部 CLI。停机整批备份后切换，保持原身份、媒体和会话路径。不会迁移目录或重写原生会话正文。恢复旧版时使用匹配的停机数据备份；旧 Pi 不理解新增上下文编辑语义，不能仅降级依赖后继续写新版会话。

收藏来自原设备浏览器时，须在原网址刷新并打开模型选择器一次，服务器才能接收旧收藏；其他设备随后读取共享结果。刷新网页加载新静态资源不会自动改变已有会话模型或全局默认值。

## 验收与发布资产

候选通过源码与归档隔离验收后，发布材料包含 `.tar.gz`、`.sha256`、清单和 `validation.json`。验证报告必须绑定实际归档 SHA256；包内不回填最终哈希。只有报告中明确通过的项目才属于本包验收范围。

本轮目标为 Linux ARM64、Node 22.x、独立身份与合成供应商，覆盖完整 Node 测试、文档/语法/依赖检查、Chromium 桌面与手机宽度、1.0.0 升级和原路径恢复。macOS、Windows、Linux x86_64、Safari、真实手机后台通知及所有真实模型/媒体供应商保留既有平台基线，不将浏览器模拟或旧包结果称为本包实机验收。

## English summary

Pivane 1.1.0 targets Pi 0.87.1 and adds project file browsing, durable task progress, searchable model selection with shared favorites, and a more compact mobile workspace. It also improves asynchronous action feedback, settings catalog refresh and update notifications.

Upgrade the complete application and its locked dependencies together. Back up stopped data, preserve existing identity and media paths, and reload the browser after activation. Original transcripts remain intact while Pi context edits apply to model requests. Validation is bound to the exact archive; local preparation does not mean the release has been published.
