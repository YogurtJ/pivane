# Pivane 1.4.0 候选 · 原生 MCP、侧聊与长会话改进

**尚未公开发布，尚未通过最终归档验收。** 当前源码应用版本为 1.4.0，锁定 Pi Coding Agent 0.99.1，推荐 Node.js 22.x（至少 22.19）。当前正式版仍为 [1.3.0](1.3.0.md)；下载版本、包 SHA256 与最终验收以该次 Release 附件为准，不能用本页或本机候选版本推断正式发布。

## 主要变化

- **Pi 0.99.1 与原生 MCP**：主线程加载官方 MCP、Codemode、Tool Search 与 llama.cpp 内置扩展；网页可管理全局／受信项目的脱敏配置、暴露策略及工具设置，所选线程的状态、重连和 OAuth 使用原有唯一 worker。保存配置与加载线程分开，未确认结果不自动重放。子 Agent 工具授权同时限制直接与 Codemode 嵌套调用。详见[原生 MCP](../MCP.md)。
- **嵌套工具与文件归属**：实时、完成和重开后的子调用归属父工具，不重复顶层计数；文件修改仅依据成功的原生记录。原生嵌套摘要不保存工具输出，历史编辑差异不可恢复，不能读取当前文件伪造当时差异。详见[文件查看](../FILE_VIEWER.md)。
- **侧聊**：首次发送才创建运行实例；独立模型与思考等级，复用搜索／收藏模型选择器，背景更新分段保留本页记录，闲置 12 小时回收，执行中不回收。新侧聊及压缩的实际用量进入精简账本，不记录侧聊正文；不新增持久历史或自动恢复。详见[侧聊](../SIDE_CHAT.md)和[用量](../USAGE.md)。
- **长会话加载**：RPC 输出逐块按 LF 分帧，避免图片大响应的重复合并；超出快路径预算的会话共享原生回退扫描并缓存经身份核实的精简元数据，不保留全文正文。后台学习扫描不重叠。原生写入使会话列表证明失效时，有界重新读取并重新核实，不复用失效结果、不重放写入。
- **使用体验**：提示词查看与编辑采用三步布局和显式加载状态；扩展已安装列表分类、原生 MCP 卡片、聊天记忆回执及纠错卡更紧凑；增加主题与字体偏好。版本页改为只读检查及可复制的独立 Agent 更新提示词，旧维护后端保留兼容，不因检查版本而执行升级。
- **锁定依赖与兼容**：统一 host Pi 依赖，内置 vendor 官方内容保持原样；保留 undici 8.11.2 修复，并在安装边界处理 Pi shrinkwrap 的 brace-expansion 5.0.12 修复。当前 Pi 与 Pivane 原生适配须一起验收，不支持单独切换 Pi。

细节见 [CHANGELOG](../../CHANGELOG.md)、[用户指南](../USER_GUIDE.md)及[API](../API.md)。

## 从 1.3.0 升级前必须核对

使用部署机器上的独立维护 Agent；不要直接停止承载当前对话的服务。先核对全部任务、Shell、侧聊、预约、媒体与配置操作，保存浏览器草稿，等待空闲；旧服务停止后完成一致的原始备份，再在独立应用目录安装准确归档，运行 `node scripts/install.cjs`（Windows 使用 `node.exe`）。新旧服务不能同时读写同一身份或调度数据库。

**只替换应用与锁定依赖，保留 Pi 身份、原生会话、认证、模型、项目、媒体、记忆、调度及其他扩展。** 固定原有数据绝对路径，尤其是 `PI_WEB_DEFERRED_FILE`；端口变化时同步调整 `PORT`、`PI_WORKSPACE_BASE_URL` 与访问地址，不另建预约队列。正常安装不自动迁移 MCP 配置或删除第三方扩展。

### 旧 pi-mcp-adapter 的重要兼容变化

本版过滤可识别的旧适配器，防止覆盖官方 `/mcp` 实现，保留原文件与包安装。不再推荐或允许新增／更新旧适配器。**保留旧配置不代表旧 MCP 能直接继续连接。**

原生 MCP 的传输、暴露策略、超时单位和 OAuth 存储不同；旧 SSE、导入／plugin、过滤及动态 header 规则可能需要人工转换。先完成只读检查和人工审查，停机整批备份后才按[迁移指南](../MCP.md#从-pi-mcp-adapter-迁移)显式转换。旧 OAuth 不自动转换，必要时重新通过原生流程授权。其他扩展不要求重装；当前 worker 必须重载或重开后核对实际能力。

旧 Codex 凭据不自动转换为新 ChatGPT 身份；登录遵循原生持久 deviceId 与认证 API，不复制或回显凭据。模型路由和媒体执行确认不因升级改变。

### 恢复边界

保存旧应用目录与停机原始数据备份。配置迁移与应用切换分开记录，回退代码不能自动撤销已转换的 MCP 配置；新服务接受消息后不得直接用旧数据覆盖新消息。恢复前停机并核对整批路径、字节及原生会话语义，不文本替换 JSONL 正文。操作步骤见[安装与恢复](../INSTALL_RECOVERY.md)。
