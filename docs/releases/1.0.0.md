# Pivane 1.0.0 · 首个正式版

Pivane 的首个正式版本，基于 **Pi Coding Agent 0.86.1**，推荐 **Node.js 22.x**。从电脑、平板和手机使用同一个自托管 AI 工作台：编码、管理项目与原生会话、跟进 Agent 任务，并连接自己的图像、视频和语音服务。

## 本版变化

- **持续保存用量**：按已验证的原生记录增量入账，支持周与自然月汇总；重启和删除会话后保留已入账历史。每五分钟后台同步，零或缺失费用按精确模型 ID 匹配官方目录补算，保留价格依据，未知型号明确标注。
- **任务结果回到来源线程**：任务查询使用可重建的元数据目录；完成结果保留原生回复并支持分页读取。来源线程空闲时实时显示结果回执，重开可恢复，不自动触发下一轮模型请求。修复工具可选参数兼容及迟到历史覆盖回执的问题。
- **扩展中心与助手**：统一浏览已安装 Packages/Skills 与精选能力；新增“检查更新”预设，先检查来源、版本和兼容性，确认后再更新。
- **完整工作台基线**：包含 RC 阶段的中英文界面、AI 会话标题、归档、系统提示词编辑、辅助模型、侧聊、媒体实验室、应用与 Pi 更新，以及后台常驻安装入口。
- **架构与兼容整理**：统一源码发现和发行清单，整理服务模块与 worker 生命周期；采用 Pivane 名称和配置别名，保留旧配置、原生会话与历史任务链接。目录迁移仍需独立的停机验证流程。

完整变化见 [CHANGELOG](../../CHANGELOG.md)，使用方式见[用户指南](../USER_GUIDE.md)。

## 下载、安装与升级

从 [1.0.0 Release](https://github.com/YogurtJ/pivane/releases/tag/v1.0.0) 下载 `pivane-1.0.0.tar.gz` 和同名 `.sha256`，核对 SHA256 后按[安装与恢复](../INSTALL_RECOVERY.md)操作；[English installation](../en/INSTALL.md)。首次安装运行 `npm ci`，配置实例后安装[后台服务](../BACKGROUND_SERVICE.md)。无需全局安装 Pi，也无需前端构建。

已有 RC 用户可升级至 1.0.0。升级前结束任务、暂停预约、保存草稿，并按指南停机整批备份。保留原数据目录和 Pi 身份，不重复注册已有服务，不把升级与项目目录改名混在一起。支持应用更新的实例可在“设置 → 版本与更新”选择正式版渠道并安装；不支持的旧实例按手动升级流程操作。版本号从 RC4 升为 1.0.0，既有 RC 发布资产不替换。

## 验收与已知范围

本包验证结果随 Release 的 `pivane-1.0.0.validation.json` 提供，`artifactSha256` 必须与下载包一致；包内不回填最终哈希，避免循环重打包。本次在 Linux ARM64、Node 22.x 上进行源码检查、隔离安装、RC4 升级、原路径恢复与 Chromium 桌面/手机宽度检查，具体通过项以该附件为准。

macOS、Windows 和 Linux x86_64 的历史 RC 验收仅作为平台基线，本包未宣称在这些系统重跑实机测试。新后台安装器的 macOS/Windows 服务与桌面入口、Safari、真实手机后台通知以及所有真实模型和媒体供应商仍未完成本包验收。浏览器与模型测试使用独立身份和合成服务，不继承用户凭据。详见[平台验证范围](../RELEASE_INSTALL_VALIDATION.md)。

Pivane 面向个人独立部署，不提供多人账户隔离；项目范围不是 Agent 工具沙箱。媒体规划不执行生成；失败或结果不确定的请求不自动重放。

## English summary

**Pivane 1.0.0 is the first stable release**, pinned to Pi 0.86.1 and recommended with Node.js 22.x. It brings the cross-device workspace, extension center, application updates and background installation together with persistent usage accounting, durable task result receipts and an extension update-check preset.

Download the archive and checksum from this release. Back up and stop an existing instance before manual upgrades; preserve its Pi identity and data directories. RC4 users can upgrade to 1.0.0 without renaming their project directories. Existing RC assets are retained.

The attached validation report binds results to the exact archive SHA256. This release is checked on Linux ARM64 with isolated identities and synthetic providers, including RC4 upgrade, recovery and desktop/mobile Chromium layouts. macOS, Windows and Linux x86_64 retain historical RC baselines; their current artifact, new OS background installers, Safari and real mobile notifications are not claimed as newly validated.
