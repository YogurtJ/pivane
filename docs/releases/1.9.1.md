# Pivane 1.9.1（Pi 1.3.0）

本版已于2026-10-22[正式发布](https://github.com/YogurtJ/pivane/releases/tag/v1.9.1)。冻结源码为 `f0c9d5d5149d5cf2e0972234884788da6acf00a4`，准确归档SHA256为 `8a166561cb89947dbd2032a03360709b08b862d76aaaccb363b26b8becf08d9c`；六项附件公开回下载后逐字节一致。标签和归档保留冻结字节，本页在主分支补记最终结果。

## 本版变化

- **大文件下载与交付**：项目文件与交付快照提供独立的受认证下载接口，超过 16 MiB 预览预算仍可下载。默认单文件下载／交付上限 512 MiB，交付组上限 1 GiB；复制采用分块读取，保留完整文件身份、哈希、分支与前后变化校验。预览预算内、签名识别的 MP4 可直接播放。详见[文件与交付](../FILE_VIEWER.md)。
- **聊天交付卡片**：成功的 `deliver_files` 结果显示文件类型、名称、大小与下载入口，小图片显示缩略图；超过五项可展开。简洁视图与刷新后历史保留卡片，回复中的文件链接带类型图标。
- **结构化提问**：默认受管工具新增 `ask_user_question`，一次提交 1–4 题，可选择选项、自写回复、跳过、前后切换后统一提交。输入区上方显示作答面板，对话保留回答摘要；取消、超时、停止、缺少 UI 与跳过分别记录，不作为默认选择或同意。默认等待 10 分钟，最长 30 分钟。详见[用户指南](../USER_GUIDE.md)。
- **微信绑定线程结果通知**：默认接收绑定线程的全部最终结果，包括网页、微信及默认跟随线程的定时任务；运行途中绑定可接收当前任务，已完成历史不补发。保留仅微信问答模式和单个定时任务关闭通知，固定原生轮次的回复与附件并持久去重；修复网页停止被微信任务锁挡住的问题。详见[消息渠道](../MESSAGE_CHANNELS.md)。
- **主题与导航**：晴空、薄荷、燕麦、石墨与夜间使用重新设计的配色和统一主题强调色；成功状态继续使用绿色。导航改为线性图标，桌面折叠后保留 Logo，支持鼠标、键盘与触屏展开；修复触屏收起后 Logo 空白。平板使用窄栏，手机五个底栏入口等宽，英文长标签可换行。
- **消息队列界面**：引导／后续消息的队列入口并入输入区状态标签行并显示数量，窄屏可换行；队列窗口按执行时机分组，取回记录独立显示，保留草稿、附件、旧后端只读展示和防重复追加行为。关闭窗口时保留用户已明确选择的输入焦点。详见[运行控制](../NATIVE_CONTROLS.md)。

Pi 1.3.0、pi-subagents 0.78.0 与 pi-hermes-memory 0.9.10 保持，依赖未升级。完整变化见 [CHANGELOG](../../CHANGELOG.md)。

## 安装、升级与恢复

1. 下载 `pivane-1.9.1.tar.gz` 及同名 `.sha256` 文件，使用 `sha256sum -c pivane-1.9.1.tar.gz.sha256` 核对；macOS 可用 `shasum -a 256 -c`，Windows 可用 `Get-FileHash -Algorithm SHA256` 比较。
2. 解压到独立新目录，用 Node 22 执行 `node scripts/install.cjs` 安装锁定依赖，不复用其他系统的 `node_modules`。
3. 升级前保存草稿和附件，等待主任务、子任务、Shell、侧聊、预约／定时投递、媒体、渠道发送与配置操作结束；按实际范围备份身份、会话、媒体、队列、配置及外部数据，再正常停机切换，保持原数据路径。
4. 启动后核对版本、受管工具、会话分支、书签、附件、队列与微信通知模式。新增受管工具需在安全空闲时重新加载 worker；线程绑定默认接收全部最终结果，需要时可改为仅微信问答。
5. 未知提交先查询原回执，不自动补发。恢复先停机核对原路径字节，再用原生 SDK 核对会话 ID、完整分支与语义；新实例已接受写入后，不用旧备份覆盖新消息。

详见[安装与恢复](../INSTALL_RECOVERY.md)、[版本与更新](../UPDATES.md)。正常升级不搬迁会话树，也不改写 JSONL 正文。

## 验收与限制

三平台准确包验收已完成：Linux ARM64 Node 1105通过/1项平台跳过，macOS 1077通过/29项平台跳过，Windows 1078通过/28项平台跳过。全量自动浏览器 macOS、Windows 首次115/115；Linux 首次114/115，失败脚本查明为验收期间上游 Pi 1.4.0 发布后，自动更新提醒卡片在窄屏遮挡下载按钮，测试夹具改为先关闭提醒后在准确包上完整通过，断言和时限未改。三平台均完成独立安装、从正式1.9.0升级、20文件原路径恢复和4文件原生语义恢复；Windows 另在真实普通权限完成安装、运行和会话导入。首次生产 audit 遇 npm 服务端故障，恢复后各平台包内审计均为零漏洞。详见[平台验证范围](../RELEASE_INSTALL_VALIDATION.md)与 Release 附件。

本版修复此前两项既有问题：共享线程显式 `/quit` 在 Shell/RPC 实际结束后同步到其他已连接页面，清除运行展示并保留各页草稿和附件；Windows 导入在文件系统边界使用长路径形式，保留规范原生路径和不覆盖目标的原子发布。需要重新打开已退出线程才能继续发送，页面内存中的草稿在刷新前仍需保存；系统路径组件和权限限制保持。行为见[运行控制](../NATIVE_CONTROLS.md)与 [Windows 指南](../WINDOWS.md)。

已知问题：一台设备在 Shell 命令运行中执行 `/quit` 后，另一已连接页面可能短暂误报“会话同步失败”，实际状态、草稿和附件均正确；主分支已修复，随下一个补丁版本发布。窄屏上的自动更新提醒卡片会暂时遮住下方内容，关闭后恢复。

Chromium 手机视口检查不证明真实手机键盘、麦克风或后台行为；Safari、Firefox、Intel macOS、Windows ARM64 与真实供应商计费不由合成服务测试证明。微信和媒体仍需用户自己的接入配置。

## English upgrade notes

Pivane 1.9.1 was released on 2026-10-22. It adds authenticated large-file downloads, compact delivery cards and structured user questions; forwards final results from bound threads to WeChat; and updates themes, navigation and the message queue interface. It preserves explicitly selected input focus when closing the queue. Pi 1.3.0, pi-subagents 0.78.0 and pi-hermes-memory 0.9.10 remain unchanged.

This release fixes stale Shell state on other connected pages after an explicit `/quit`: terminal notification follows actual Shell/RPC shutdown, preserves local drafts and attachments, and does not automatically reopen the runtime. Windows imports use extended-length paths at filesystem boundaries while retaining canonical native paths and atomic no-replace publication. Reopen the thread explicitly to continue; save in-memory drafts before refreshing. OS component-length and permission limits still apply. Known issue: after an explicit `/quit` on one device while a Shell command runs, another connected page may briefly show a false "session sync failed" toast; state, drafts and attachments are correct, and the fix ships in the next patch release.

Exact-archive acceptance passed on Linux ARM64, Apple Silicon macOS and Windows x64, including independent installation, the real 1.9.0 upgrade and original-path restoration. One Linux browser first-run failure was traced to an upstream update reminder covering controls in narrow viewports and passed after a test-fixture fix with unchanged assertions; see the validation attachments. All six published assets were downloaded again and matched the frozen bytes. Install into a separate directory, preserve data paths, save drafts, back up and stop the old instance before switching. Reload managed workers while idle to enable the new tool. Check the WeChat notification mode after upgrading. Do not replay uncertain submissions or restore an old backup over newly accepted messages.
