# 定时任务与主线程

本机或自托管实例须确认后端报告 `scheduledTasks:true`、目标 worker 加载 `cron-v1`；只刷新旧版网页不会更新后端。任务页初次读取时显示加载状态；读取失败可重试。普通 HTTP 局域网地址不提供浏览器 `crypto.randomUUID` 时，创建任务仍通过 `crypto.getRandomValues` 生成随机任务 ID。

在工作台导航进入“定时任务”（手机位于“更多功能”），可以创建、编辑、复制、暂停和删除任务，也可以手动运行一次。线程操作菜单提供“创建定时任务”，自动填入该线程。身份概览的“主线程与定时任务”打开该身份的任务列表。

## 创建任务

1. 选择指定线程，或一个助手身份的主线程。普通无身份线程也可作为目标。管理线程不接受定时任务；身份归属由原生线程决定。
2. 选择每天、工作日、自定义五段 cron 或单次日期，并核对未来五次时间。周期时间使用明确的 IANA 时区，例如 `Asia/Shanghai`；单次日期按当前设备时区输入，预览按所填目标时区显示。
3. 可指定“生效时间”，自动执行只会安排在该时刻及以后；留空立即生效。此字段按当前设备时区输入，预览按任务时区显示。手动“运行一次”仍可提前执行。
4. 填写任务说明。文字模式只允许生成文字和使用静默结束工具；工作模式使用原线程的工具与权限。任务会使用目标线程的现有上下文。首版不提供自动媒体生成或跨线程委派。
5. 可展开执行策略：跟随目标线程模型，或固定供应商、模型和该模型支持的思考等级；设置错过策略、用户活动条件和预算。
6. 新任务默认停用。勾选“保存后启用”或保存后点击“启用”，服务才会自动执行。“运行一次”会实际调用模型，也受预算和互斥限制。

暂停阻止后续触发并取消尚未提交的排队运行，不等于中止正在执行的工作；正在运行的一次需单独点击“停止”。删除任务保留已有线程、回复与执行记录，不撤销工作产生的副作用。

## 主线程

每个 profile 最多一个主线程，按需创建，也可以指定已有的同身份普通线程。任务编辑器选择“身份的主线程”后，在明确的工作目录中指定或创建。创建的是普通原生持久会话，未自动绑定逻辑助手项目；在助手对话中按原有未分类规则显示。

主线程引用不改变线程历史或身份。更换主线程后，尚未开始的任务使用新目标；已经提交的运行保留原目标。删除主线程会标记引用失效并暂停相关任务，不自动重建。重新指定目标后显式启用任务。禁用或缺失的身份不能启动新定时运行；运行实例尚未加载最新身份配置时需空闲后重开。

创建响应不确定时先刷新核对；保留同一请求 ID，不重复创建。若页面提示创建待核对，在线程列表找到已保存的会话再指定为主线程。

## 时间与恢复

五段表达式为“分钟 小时 日期 月份 星期”，支持数字、列表、范围和步长，星期日可写 0 或 7；日期与星期同时限定时按通常 cron 的 OR 语义匹配。不支持秒字段、自然语言、`@` 别名或 `L/W/#` 扩展。预览最多向前检查八年。夏令时不存在的时刻跳过，重复的本地时刻只选择首次出现。

- **直接跳过**：服务离线时错过的触发不补发。正常运行时容许一分钟调度／线程空闲窗口，超过后记为跳过，避免迟到问候。
- **补最近一次**：宽限期 1–1440 分钟内只选择最近的一次触发。不会把停机期间所有任务集中补跑。
- **线程忙碌**：等待，不插入用户的当前任务。每任务最多一条未结束运行；后续重叠触发记录为跳过。全实例最多同时执行两项。
- **不确定结果**：提交前持久占位，原生线程按 run ID 去重。重启时提交中／运行中标为不确定，不自动重放；已打开线程中存在完成回执时可核对恢复。否则先查看线程，再选择“核对并结束”，恢复模型／工具设置后结束这一项，不重新执行。

定时调度由服务端负责，浏览器可以关闭。worker 可按原有条件在无订阅且空闲 15 分钟后退出，到点由 Supervisor 启动同一线程的唯一受管 worker。未来触发不阻止维护；正在派发、保存、执行或恢复的工作参与生命周期与停机判断。

## 静默与预算

“今天此时之后有用户消息则跳过”只检查目标线程当前原生分支的用户消息，按任务时区判断日期；不把 Agent 消息和定时任务当作用户回复。命中时不调用模型。否则模型也可以使用 `cron_silent` 明确静默结束，运行记录保留但不发送完成提醒。

每任务与实例总预算均有每日次数、Token 和可选估算美元限额，统一按 UTC 日统计。单次可设模型调用次数、Token 预算和最长时长。启动前预留额度；取得用量后结算。不确定执行保留预留值，未知费用不能当作免费；价格不明时拒绝带金额上限的自动执行。

这是费用控制与估算，**不是供应商扣款的硬上限**：Token 在调用边界检查，已经发出的请求可能超额；停止请求也要等待实际结束。金额预留按模型目录价格估算，第三方中转差价、缓存预热、压缩或工具嵌套请求／额外收费不保证全部覆盖。工作模式具备原线程系统权限，不能靠预算字段把任意 Shell、扩展或外部服务变成费用沙箱。文字模式适合问候与简报。

默认每任务每天 8 次、200000 Token；实例总量每天 40 次、400000 Token。默认单次 4 次模型调用、32000 Token、300 秒。最多 100 个任务记录（包括已删除记录）和 10000 次运行记录，达到容量后拒绝新增，不自动删除历史。页面每任务显示最近 100 次。暂停／删除任务不会删除统计或释放已消耗预算。

## 数据与接口

私有调度配置、主线程引用、占位和用量元数据保存在 `<agentDir>/pivane-cron/scheduler.sqlite`。使用 SQLite FULL 事务和私密权限；同一原生身份只允许一个调度器持有者。备份完整身份目录时包含此目录。任务说明、回复和原生执行回执保存在唯一原生会话中；数据库不复制回复正文。

接口沿用工作台认证、Origin 校验和 `no-store`；内部 worker 凭据不能作为管理授权。

| 接口 | 参数与行为 |
|---|---|
| `GET /api/pi/cron` | 任务、主线程、实例预算、今日占用、最后运行与容量；有调度故障时包含 `schedulerError` |
| `PUT /api/pi/cron/jobs` | 稳定 UUID `id`；更新带 `revision`；`name,prompt,enabled,mode,target,schedule,model,misfire,condition,execution,budget` |
| `POST /api/pi/cron/jobs/:id/actions` | `revision,action`；`pause/resume/delete/run/stop/acknowledge`；run 必须带稳定 UUID `requestId`，stop/acknowledge 带 `runId` |
| `GET /api/pi/cron/jobs/:id/runs` | 最近 100 项，包含原生结果 entry ID、实际目标、模型和用量，不复制回复 |
| `POST /api/pi/cron/preview` | `{schedule}`，返回最多五个毫秒时间戳 |
| `GET/PUT /api/pi/cron/limits` | GET 返回 `{limits,revision}`；PUT 带相同 revision 和新 limits |
| `PUT /api/pi/cron/homes/:profileId` | `{revision,cwd,sessionId}` 指定线程；或 `{revision,cwd,create:true,requestId,language?}` 创建并指定 |
| `GET /api/pi/cron/models?cwd` | 真实可用模型、思考等级及默认值 |

`target` 为 `{kind:'thread',cwd,sessionId}` 或 `{kind:'profile',profileId}`。`schedule` 为 `{kind:'cron',expression,timeZone}` 或 `{kind:'once',at,timeZone}`。`startsAt:null|毫秒时间戳` 指定自动执行的最早生效时刻，允许未来八年内；保存、启用和预览均应用该下限。`model:null` 跟随线程，否则为 `{provider,modelId,thinkingLevel}`。`misfire:{policy:'skip'|'latest',graceMinutes}`；`condition:null` 或 `{kind:'no-user-since',time:'HH:mm'}`；`execution:{maxCalls,maxTokens,maxDurationSeconds}`；`budget/limits:{maxRunsPerDay,maxTokensPerDay,maxCostPerDay:null|number}`。

运行状态为 `waiting/dispatching/running/completed/silent/skipped/failed/error/stopped/cancelled/uncertain`。修订冲突返回 409 并保留本地草稿。响应不确定先查询原 ID；不要生成新 ID 重复运行。运行未结束时拒绝编辑／删除任务，暂停仍可用。

## 从其他调度器迁移

先以停用状态建立任务，核对时区、模型、工作目录、提示词与投递目标，再受控试跑。选定切换时间，确认旧任务没有正在运行或待交付结果，暂停旧调度器中的对应任务并核实后，再启用新任务。从切换后的下一次计划开始，不补发历史问候。保留旧配置用于回退，回退时先停用新任务再恢复旧任务。

旧服务的消息平台、工具名称、图片路径和技能不是可直接移植的执行能力，需逐项适配。首版文字任务不执行旧提示词中的自动生图。
