# Agent 任务线程

在正式线程 A 中让 Agent “新开一个线程处理这件事”，Agent 可以创建同一项目下的正式线程 B、保存完整任务说明并立即启动 B。A 保持当前会话，创建回执提供“打开任务线程”；B 的任务说明标为“来自 Agent 的任务”，并可返回来源线程。用户可以进入 B 继续对话，刷新后任务说明仍保留。

此能力需要运行后端 `/api/pi/status.agentThreads=true`，并由已加载新扩展的持久 worker 提供 `agent_thread` 工具。仅修改源码或刷新网页不会更新旧后端/worker。临时线程和侧聊不提供此工具。

项目目录迁移后，历史任务记录保留当时的 cwd。点击回执或来源链接时，网页通过现有项目解析接口核对旧路径是否仍指向当前项目，再从当前项目的原生会话列表查找 ID；保留旧路径别名即可继续使用历史链接，不需要改写消息正文。不同项目的引用不能借此切换线程，迟到解析也不能抢回已经切换的页面。

## 使用与默认配置

可以直接说：“新开一个线程，只读审查这个接口，完成后把结论留在新线程里。”任务已经明确授权时直接创建和执行，不增加固定的二次确认。复杂任务先在 A 中明确目标、必要背景和允许修改的文件，再交办。

指定模型时使用实际模型目录中的供应商与模型 ID；也可以要求 Agent 先列出可用选项。模型与思考等级未指定时，读取项目适用的 Pi 新线程默认配置，不继承 A 当前临时选择的模型。没有已配置且可用的默认模型时拒绝创建，需指定模型或配置默认值。当前独立模型校验使用 ModelRuntime 目录，依赖扩展运行时注册的特殊模型可能不能用于创建任务。

明确指定的模型不可用、指定的思考等级不受支持时，创建前拒绝。默认思考等级不适用时，选不高于该等级的最高可用等级；没有这样的等级时选模型的最低可用等级。没有配置默认思考等级时使用 medium，再按能力调整。回执显示实际配置。配置在创建时冻结，不会因 A 后续切换模型而改变。

创建回执是当时的状态快照；最新运行状态看 B 的线程列表状态或让 A 按任务标识查询。停止 A 不停止 B；需要停止 B 时进入 B 使用原有停止操作。两个线程共享项目目录，没有自动 worktree 隔离，应避免同时修改同一文件。

## 内容与失败处理

- 只发送任务说明中的文字；不自动继承 A 的完整历史、系统提示或附件。
- 任务说明以原生 custom message 保存，真实来源另存结构化元数据；不伪装为用户发言。Agent 来源消息不扩大用户已有授权。
- 任务先保存再启动。启动失败时保留原 B 和任务内容，回执显示已保存或待核实；进入同一个 B 检查，必要时发送“继续执行上面的任务”。不自动补发。
- 同一来源线程及 requestId 定位同一个任务。相同请求返回已有 B，不再启动；相同标识但不同内容拒绝。请求中断后先查询同一标识，不换标识重新创建。
- 去重依赖原生任务记录仍存在；删除 B 后不保留独立去重数据库。不要把删除后的新请求当作安全重试。
- 每个来源最多三个未结束任务，最多三层嵌套；全实例同时准备最多三个创建请求。已保存但尚未执行的任务也占未结束名额，手动继续并结束或显式删除后释放。项目超过 2000 个会话或累计会话文件超过 64 MiB 时拒绝任务查询/创建，避免无界扫描。

当前不提供任意已有线程互发消息、自动结果回传、级联停止、跨项目创建或只创建空线程。结果保留在 B，用户可查看并继续对话。

## 工具与内部接口

`agent_thread` 接受 `action=create|status|models`：

| action | 参数 | 行为 |
|---|---|---|
| create | requestId、title、message；可选成对 provider/modelId、thinkingLevel | 同项目创建并立即启动 |
| status | requestId | 只读查询来源线程自己的请求，不启动 worker |
| models | 可选 query | 可用模型、支持等级及默认配置；工具最多返回 80 项/50 KiB |

requestId 为 1–160 个字母、数字、下划线、点、冒号或短横线；title 为 1–120 字符，message 为 1–40000 字符。来源不从工具参数接收，而从存活 worker 身份取得。

私有 POST `/api/pi/agent-threads/{create,status,models}` 使用受管 worker 的短生命周期凭据，限定这三个端点，继续检查 Origin。工作台 Cookie/访问 Token、媒体或扩展助手凭据不能代替来源 worker；凭据不会出现在模型输入、回执或 URL 中。HTTP models 返回最多 5000 项目录，query/80 项限制在工具输出端处理。参数中的目标路径和源 sessionId 不接受覆盖。

创建与查询回执包含 `session:{id,cwd,name}`、requestId、source、model、thinkingLevel、status；复用增加 reused=true，启动未确认增加 notice。正在准备时 status 查询只返回 requestId 和 preparing。其他状态包括 saved、submitted、uncertain、completed、error、stopped，活动 worker 优先返回实际运行阶段。HTTP 成功仅表示创建/查询已处理，不代表任务执行成功。

`/api/pi/activity.agentThreadLaunches` 计入准备中的创建请求，维护空闲检查和停机等待均覆盖该阶段。启动通过目标唯一 worker 的受保护私有命令，未知/迟到回执继续截获，不广播给浏览器。任务内容、模型选择、来源、提交与终态使用原生 SessionManager/custom entries，不维护第二份聊天记录。

## 验证

Node 合成供应商测试覆盖真实 Pi RPC、默认和指定模型、思考等级拒绝/调整、来源身份、立即执行、去重、启动失败、手动继续、worker 重建及私有迟到响应；并发专项检查预占互斥和层级/数量限制。Chromium 合成页面覆盖中英文与 1440、393、320px，检查任务卡片、纯文本来源内容、双向跳转、实际子项宽度与 pageerror。真实供应商行为和其他操作系统以对应版本实机验收为准。
