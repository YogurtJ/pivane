# Agent 任务线程

在正式线程 A 中让 Agent “新开一个线程处理这件事”，Agent 可以创建同一项目下的正式线程 B、保存完整任务说明并立即启动 B。A 保持当前会话，创建回执提供“打开任务线程”；B 的任务说明标为“来自 Agent 的任务”，并可返回来源线程。用户可以进入 B 继续对话，刷新后任务说明仍保留。

此能力需要运行后端 `/api/pi/status.agentThreads=true`，并由已加载新扩展的持久 worker 提供 `agent_thread` 工具。仅修改源码或刷新网页不会更新旧后端/worker。临时线程和侧聊不提供此工具。

项目目录迁移后，历史任务记录保留当时的 cwd。点击回执或来源链接时，网页通过现有项目解析接口核对旧路径是否仍指向当前项目，再从当前项目的原生会话列表查找 ID；保留旧路径别名即可继续使用历史链接，不需要改写消息正文。不同项目的引用不能借此切换线程，迟到解析也不能抢回已经切换的页面。

## 使用与默认配置

可以直接说：“新开一个线程，只读审查这个接口，完成后把结论留在新线程里。”任务已经明确授权时直接创建和执行，不增加固定的二次确认。复杂任务先在 A 中明确目标、必要背景和允许修改的文件，再交办。

指定模型时使用实际模型目录中的供应商与模型 ID；也可以要求 Agent 先列出可用选项。模型与思考等级未指定时，读取项目适用的 Pi 新线程默认配置，不继承 A 当前临时选择的模型。没有已配置且可用的默认模型时拒绝创建，需指定模型或配置默认值。当前独立模型校验使用 ModelRuntime 目录，依赖扩展运行时注册的特殊模型可能不能用于创建任务。

明确指定的模型不可用、指定的思考等级不受支持时，创建前拒绝。默认思考等级不适用时，选不高于该等级的最高可用等级；没有这样的等级时选模型的最低可用等级。没有配置默认思考等级时使用 medium，再按能力调整。回执显示实际配置。配置在创建时冻结，不会因 A 后续切换模型而改变。

创建回执是当时的状态快照；最新状态可在来源线程的“任务结果”面板或按任务标识查询。停止 A 不停止 B；需要停止 B 时进入 B 使用原有停止操作。两个线程共享项目目录，没有自动 worktree 隔离，应避免同时修改同一文件。

## 大项目查找

任务查找使用可丢弃的内存任务目录，按原生 header 身份和任务 custom entries 建立关系，不调用全项目会话正文列表后再逐个打开 SessionManager。未变化的文件核对描述符身份后复用；变化的文件单独重新扫描。重启、缓存淘汰后分批重建，不复制或改写原生聊天。

首次整理显示进度，create/status/result 可返回 HTTP 202、`code=TASK_INDEXING`、`status=indexing` 和 coverage。此调用尚未进入创建动作；保留同一 requestId，待整理完成后查询，确认不存在时可用原参数再次创建。整理未完成、文件损坏、未完成 LF 行、链接或身份冲突不等于“任务不存在”。不更换 requestId 重试未知创建结果。

不再按全项目64MiB或2000个会话一律拒绝。每批最多读取8MiB，并在约100ms处理片段后让出事件循环；单行解码上限32MiB、每项目最多50000个文件、选取的任务元数据预算32MiB，最多缓存8个项目。目录枚举、文件属性检查和单条 JSON 解码不承诺100ms硬实时完成。缓存只含查找信息、结果预览和已读标记；没有第二份权威聊天历史。

## 结果回执

`GET /status.agentTaskResults=true` 表示后端支持结果回传。新创建的任务每轮结束保存独立 run 标识、原生回复 entry ID 和最多6000字符的纯文本预览，不额外调用模型总结。来源线程显示任务状态、结果预览、完整线程入口和已读标记；预览截断会明确提示。结束状态不是目标验收证明，错误、中止和需要处理分别显示。

来源 worker 空闲后，通过其私有命令写入原生 custom message，不触发新模型轮次。来源忙碌时面板仍可查看结果，待空闲再纳入会话；来源未打开时不为通知启动 worker，下次打开后补收。结果是 Agent 来源，不增加用户授权。主 Agent 可用 status 查看最新预览，用 result 分页读取指定原生回复。

回执绑定来源 ID、目标 ID、requestId 和 run 标识；重复事件、响应不确定及重开 worker 均先核对原生回执。已读通过来源 worker 保存；来源忙碌或未打开时不能写已读。子线程继续执行产生新的一轮结果，旧结果保留。界面显示最近100份结果和最多100个进行中任务，旧原文仍在目标线程；后台逐批补收尚未交付的结果。

旧任务仍可按原 requestId 查询、打开原线程；没有新回传标记的旧任务不会在升级后集中推送历史通知。任意既有线程互发消息、级联停止、跨项目创建和自动唤醒主 Agent 均不在此能力内。

## 内容与失败处理

- 只发送任务说明中的文字；不自动继承 A 的完整历史、系统提示或附件。
- 任务说明以原生 custom message 保存，真实来源另存结构化元数据；不伪装为用户发言。Agent 来源消息不扩大用户已有授权。
- 任务先保存再启动。启动失败时保留原 B 和任务内容，回执显示已保存或待核实；进入同一个 B 检查，必要时发送“继续执行上面的任务”。不自动补发。
- 同一来源线程及 requestId 定位同一个任务。相同请求返回已有 B，不再启动；相同标识但不同内容拒绝。请求中断后先查询同一标识，不换标识重新创建。
- 去重依赖原生任务记录仍存在；删除 B 后不保留独立去重数据库。不要把删除后的新请求当作安全重试。
- 每个来源最多三个未结束任务，最多三层嵌套；全实例同时准备最多三个创建请求。已保存但尚未执行的任务也占未结束名额，手动继续并结束或显式删除后释放。任务目录未核实完成前不创建或重放任务。

任务正文和完整结果保留在原线程，用户可以进入该线程继续对话。

## 工具与内部接口

`agent_thread` 接受 `action=create|status|models|result`：

| action | 参数 | 行为 |
|---|---|---|
| create | requestId、title、message；可选成对 provider/modelId、thinkingLevel | 同项目创建并立即启动 |
| status | requestId | 只读查询来源线程自己的请求，不启动 worker |
| result | requestId；可选 resultId、offset | 只读原生任务回复，每页最多8000字符，nextOffset 指向下一页；总读取截止20秒，不返回工具/思考/系统内容 |
| models | 可选 query | 可用模型、支持等级及默认配置；工具最多返回 80 项/50 KiB |

工具入口在参数校验前按 action 选择适用字段，兼容模型把全部可选字段都填写出来的情况。空字符串或 null 的可选模型设置视为未指定；非空的显式选择仍需通过模型与思考等级校验。创建请求不携带 resultId/offset/query；直接调用 REST 创建接口时仍拒绝额外字段。requestId、title、message 等当前操作必需的内容不能用空值替代，未知身份或路径字段不会被静默接受。

requestId 为 1–160 个字母、数字、下划线、点、冒号或短横线；title 为 1–120 字符，message 为 1–40000 字符。来源不从工具参数接收，而从存活 worker 身份取得。

私有 POST `/api/pi/agent-threads/{create,status,models,result}` 使用受管 worker 的短生命周期凭据，限定这四个端点，继续检查 Origin。工作台 Cookie/访问 Token、媒体或扩展助手凭据不能代替来源 worker；凭据不会出现在模型输入、回执或 URL 中。HTTP models 返回最多 5000 项目录，query/80 项限制在工具输出端处理。参数中的目标路径和源 sessionId 不接受覆盖。

创建与查询回执包含 `session:{id,cwd,name}`、requestId、source、model、thinkingLevel、status；复用增加 reused=true，启动未确认增加 notice。正在准备时 status 查询只返回 requestId 和 preparing。其他状态包括 saved、submitted、uncertain、completed、error、stopped，活动 worker 优先返回实际运行阶段。HTTP 成功仅表示创建/查询已处理，不代表任务执行成功。

普通工作台身份可用 `GET /api/pi/agent-threads/results?cwd=...&sourceSessionId=...` 查看来源线程的 tasks/results/coverage；`POST /api/pi/agent-threads/read` 接受 cwd、sourceSessionId、deliveryId，核对归属后仅由已打开且空闲的来源 worker 写已读。私有任务凭据不能调用这两个工作台端点。

`/api/pi/activity.agentThreadLaunches` 计入准备中的创建请求；agentTaskIndexing 和 agentTaskReturns 报告读取/交付工作，维护空闲和停机等待均覆盖这些阶段。启动通过目标唯一 worker 的受保护私有命令，未知/迟到回执继续截获，不广播给浏览器。任务内容、模型选择、来源、提交与终态使用原生 SessionManager/custom entries，不维护第二份聊天记录。

## 验证

Node 合成供应商测试覆盖真实 Pi RPC、默认和指定模型、思考等级拒绝/调整、来源身份、立即执行、去重、启动失败、手动继续、worker 重建及私有迟到响应；并发专项检查预占互斥和层级/数量限制。Chromium 合成页面覆盖中英文与 1440、393、320px，检查任务卡片、纯文本来源内容、双向跳转、实际子项宽度与 pageerror。真实供应商行为和其他操作系统以对应版本实机验收为准。
