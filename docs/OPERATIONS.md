# Pivane 运维与排障

安装、更新、停机备份和恢复以[INSTALL_RECOVERY.md](INSTALL_RECOVERY.md)为主。本文描述通用运维，不提供任何维护者机器的默认配置。

## 运行实例核对

检查实际代码目录、Node版本、启动用户、HOST/PORT及独立的Pi、媒体、项目、预约路径。进程变量优先于.env；.env中的`$HOME`、`~`不会自动展开。多个实例不能共用同一个身份或预约文件。

```bash
node --version
npm --version
curl -fsS http://127.0.0.1:11408/api/access/status
```

将端口替换为自己的实例。启用访问验证时，使用浏览器Cookie或受控程序Bearer读取私人API；不要把Token放URL或日志。

- `/api/pi/status`：加载的Pi版本、项目范围与能力标记。
- `/api/pi/activity`：服务管理的持久runtime、预约、配置、导入导出及标题生成活动摘要（`titleGenerations` 非零时仍有请求未结束）。
- `/api/pi/media/lab/activity`：媒体执行和接入操作摘要。

401/403或未知状态不能证明空闲；activity也不能证明外部CLI、扩展远端进程或供应商任务停止。后台侧聊、等待确认及内存取回内容同样需要处理。

## 启动与退出

前台运行用于试用或排障。停止前结束任务、保存草稿；备份前暂停预约。通过原控制台 Ctrl+C 或后台服务的正常退出方式停机并等待退出。SIGINT/SIGTERM 共用异步清理，重复信号不重复执行，失败以非零状态退出。关闭窗口、强制结束或断开 SSH 不保证正常停机，平台操作见[后台常驻](BACKGROUND_SERVICE.md)。

可以自行使用系统服务管理器，但应明确WorkingDirectory、Node绝对路径、用户、PATH和所有数据目录。不要覆盖其他应用的systemd、HTTPS代理、防火墙或网络隧道。当前源码的`node server.js`和`npm start`仍使用受管启动器，但设置页只读显示版本并提供独立 Agent 提示词，不再显示更新、备份或重启入口。原有维护接口和恢复工具暂留兼容；升级由部署机器上的独立 Agent 或管理员在安全窗口核对并执行。它不创建系统服务，详情见[版本与更新](UPDATES.md)。

直接运行源码时，静态资源更新可刷新页面加载，后端更新需空闲重开服务。受管Pi安装使用代码快照，原源码目录的后续修改不自动进入运行快照；源码开发使用独立身份和`npm run start:direct`。保存原生配置一般只对新runtime生效，刷新浏览器可能仍连接旧worker。会话详情可核对当前实际资源；按页面提示空闲重开或`/quit`后重新打开。

## 常见问题

| 现象 | 核对方式 |
|---|---|
| 网页打不开 | 确认进程、启动日志、HOST/PORT；localhost是浏览器本机。其他设备访问还需地址/防火墙/网络和访问验证配置。 |
| 超长或含大图的会话导致加载停滞 | RPC 输出逐块按 LF 分帧，避免对巨大图片响应反复复制／扫描；列表对大文件与大记录沿用原生读取，并缓存经文件身份校验的精简元数据，并发读取共享扫描。首次历史读取仍可能较慢；不需要删除或改写原生会话。 |
| 项目或线程消失 | 检查启动用户、PI_CODING_AGENT_DIR、项目绝对路径、PI_PROJECT_ROOTS和隐藏项目；不要创建空身份覆盖旧数据。 |
| 模型不存在/不能发送 | 先完成供应商登录，检查真实模型ID/协议；等待空闲目录刷新，必要时用页面引导刷新。不要自动换模型或重发原问题。 |
| OAuth回调失败 | 回调localhost指服务器；使用服务方提供的设备码或手动回调。没有后备交互的服务可能需要服务器本机认证。 |
| 新配置未加载 | 比较保存配置与当前runtime实际加载来源/trust；任务结束后显式重开。 |
| 打开线程提示启动超时或 `get_state` 超时 | 冷启动需加载 Pi 与全部已启用扩展，Windows 文件扫描可能使首次打开明显变慢。服务日志中的 worker 就绪耗时接近上限时，在实例配置中调大 `PIVANE_WEB_STARTUP_TIMEOUT_MS`（最多 170000）后空闲重启；频繁失败时在扩展管理中逐个停用最近安装的扩展定位原因。空闲却无回应的旧 worker 会在重新打开线程时自动替换，运行中的任务不会被终止。 |
| 文件/搜索/用量不可用 | 检查原生组件及manifest、项目边界、UTF-8/大小/并发预算、文件是否变化；不能移除描述符校验。 |
| 用量不完整或费用不同 | 缺失/超限须保留提示；费用为历史配置估算，侧聊/临时/媒体规划不纳入持久统计。 |
| 媒体模型为空 | 首次安装正常；在媒体模型管理添加自己的服务/Key/模型。模板支持不等于真实生成权限。 |
| 媒体失败或结果不明 | 核对供应商任务和历史、下载来源、额度与参数；不会自动重试。 |
| 通知未出现 | 页面需要运行/权限；后台推送需HTTPS、浏览器服务联网及系统允许。测试接受不代表手机显示。 |
| 设置409冲突 | 保留输入，刷新核对后重新编辑；成功提交后重读失败也不能直接重放写入。 |

遗忘访问Token的本地恢复步骤见[访问控制](ACCESS_CONTROL.md)。原生Shell`!!`仍留历史，历史导航不会撤销外部副作用。HTML导出可能包含私密正文、思考、系统提示和工具定义，分享前检查。

## 日志与安全

前台查看标准输出/错误；使用服务管理器时查看自己服务的日志。分享前移除Token、Cookie、Provider响应中的秘密、私有URL、正文与不必要的路径。不要读取并输出auth.json来证明认证可用；使用脱敏状态。

备份可能包含凭据、预约正文和媒体，存放在非公开目录并保护/加密，不能放public/downloads或公开仓库。目录范围和进程身份隔离不等同于恶意代码沙箱。

## 开发验证

源码维护见[开发文档](development/README.md)。独立测试必须隔离身份、媒体、预约、项目、URL和继承认证；仅换端口或PI_MEDIA_PROFILE=clean不够。用户正常运行不要求安装Playwright或编译器来重跑维护者测试。
