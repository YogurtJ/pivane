# 架构检查记录

本记录针对 RC4 后的源码维护结构，结论来自实现、开发入口和现有测试的对照。平台与运行实例的实际验收另行记录，不由本页推断。

## 本轮处理

| 问题 | 影响 | 调整 |
|---|---|---|
| 语法检查、测试、发行和受管快照分别枚举文件，部分只扫第一层 | 模块移入子目录后可能漏检或漏包 | 统一 `source-files.cjs`；递归发现、私有路径排除和链接拒绝一起验证 |
| 网关直接检查大量 worker 字段，回收使用另一套判断 | 新任务类型容易漏进维护/回收边界；队列可能在看似空闲时被忽略 | worker 提供统一生命周期投影，Supervisor 给出维护空闲；网关停止复制字段列表 |
| 网关同时承载设置和媒体的 HTTP 细节 | 修改独立功能需要理解大段不相关路由 | 提取 `server/routes/settings.js` 与 `media.js`，保持原有服务、锁、状态码和执行票据 |
| 品牌残留与兼容规则散落，旧记录仍在使用 | 直接替换标记会丢失任务、助手、标题和来源解释 | 新标记用 Pivane，旧标记和私有响应在兼容边界识别；新数据默认名与既有文件选择分开 |
| 项目目录、会话目录、header cwd 与父会话路径分别关联 | 只改源码目录会造成会话不可发现；从文件名推断 ID 可能错误 | 离线结构迁移保留原始字节，验证原生身份、完整树、leaf 和书签；历史正文不替换 |
| 递归树验证对很深的会话不可靠 | 长期使用积累的历史可能在迁移检查时溢出 | 验证原生 entries/branch 和完整连接关系，加入深长历史测试 |
| 路线图和 CHANGELOG 混有已完成的待办/未发布标签 | Agent 可能重复开发，或误判功能可用状态 | 以版本说明核对并纠正状态，区分当前源码与发布资产 |
| Agent 当前入口混合长期规则与历史运维过程 | 上下文加载量大，过期路径和授权容易被误用 | 简短入口指向模块导航与私有当前状态；历史信息按需查阅 |
| 验证要求没有区分迭代、交付、文档和发行 | 简单修改重复执行高成本流程 | 制定变更类型矩阵，保留源码交付、数据迁移和发布的完整验证要求 |

## 保留的设计

- 继续采用单体部署和内部功能服务。现有跨模块问题主要来自状态归属和重复规则，尚无证据需要增加网络服务边界。
- 保留原生 SessionManager、唯一 worker、严格 LF、描述符身份检查与私有票据。它们保护实际的数据和执行语义，不能通过减少检查来降低代码复杂度。
- 保留原生配置、媒体、项目偏好之间的明确责任。可重建的展示缓存不成为第二份聊天事实。
- 保留已有 RPC/API 路径和浏览器偏好，新的命名通过兼容入口推进。历史版本和原始会话不做全文改写。
- 保留普通浏览器脚本与现有测试体系。引入新的前端构建或语言栈需要具体收益和迁移验证，不能仅以文件较大为依据。

## 持续关注

`public/pi-chat.js` 仍集中协调连接、项目列表、当前线程和草稿。下一次修改这些领域时，应先明确状态所有者，再逐个提取组件，覆盖线程切换、重连和迟到结果；一次性拆散闭包会扩大验证范围，单纯减少行数不改善接口。

`server.js` 仍包含旧媒体执行器和历史管理。新媒体能力应进入现有 lab/provider 服务，旧入口在明确兼容与停用策略后逐项收敛。现有独立用户仍可能使用旧接口，不能根据默认实验室未启用就删除适配器。

任务线程查找目前受会话数量和读取预算限制，大项目需要继续关注元数据读取成本；任何改进都要保持原生身份绑定、稳定 requestId 和不确定请求不重放。性能优化不能建立与原生记录不一致的长期任务历史。

平台原生组件、第三方插件的精确版本适配、持久批量媒体与跨平台会话迁移仍有各自验证成本。已有合成测试不代表所有真实环境通过；这些限制应保留在对应功能/版本说明，避免扩散成全项目一律禁止的规则。

## 完成判定

使用一个代表性的功能需求，能够从模块导航找到职责所有者、相关契约与验证入口；新增子目录内模块不会漏检或漏包；旧会话与配置可读取；目录迁移有原始备份、映射和语义证据；私有资料不进入公开文件集合。持续关注项保留具体原因，不以代码行数或文档数量作为验收结论。
