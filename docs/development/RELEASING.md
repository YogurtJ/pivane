# Pivane 发布准备

## 版本边界

package.json的应用版本、Pi依赖版本和快照时间戳是不同概念。npm run pack:release生成按应用版本命名的包，TRIAL_MANIFEST.json含appVersion/piVersion，保留原文件名与version=1格式。`/api/pi/status.version`表示加载的Pi版本；它不能单独证明网页和后端属于同一候选包。用压缩包SHA256及TRIAL_MANIFEST逐文件核对构建内容。

发布包绑定源码提交和归档 SHA256。主分支文档可以补记发布结果，不改变冻结标签或归档；本地打包成功不表示已经[公开发布](https://github.com/YogurtJ/pivane/releases)。名称兼容与目录迁移见[命名与迁移](NAMING.md)。

## 本机部署与公开发布的边界

本机局部功能和共享基础能力部署按 [验证矩阵](WORKFLOW.md#验证矩阵) 选范围；不因生成 `pack:trial` 或切换后端就要求每次做三平台发行验收。仍保留运行版修复比对、独立候选安装与探针、备份、空闲切换、就绪核验和不重放边界。

公开发布必须有可追溯的验证证据，覆盖所宣称的平台及相关安装、升级、停机和恢复能力。**归档 SHA256 改变只表示产生了新包，不自动使全部测试失效。** 最终记录绑定实际发布包，并区分本次执行与按下节复用的结果；不能把复用写成该包重新跑过全量，也不能用源码语法检查冒充运行验收。

## 验证范围与证据复用

先比较本次改动与最近可追溯的验证基线，再选执行范围；基线可以来自上一正式版或本轮已完成的候选。没有可用基线，或运行行为、依赖、环境的变化无法可靠界定影响时，才建立相应全量基线。不同平台不能互相冒充实机证据。

| 实际变化 | 本次验证 |
|---|---|
| 说明文档、规则、README | 文档检查及发行清单/内容核对；不跑应用测试，不因补写发布记录重新打包 |
| 仅测试、夹具或等待条件 | 保留失败现场，验证修改后的相关脚本及原断言；复用实现、依赖和环境未受影响的应用验证。测试运行器或共享夹具变化须覆盖受其影响的测试，不能按“测试文件”一概豁免 |
| 局部产品修正 | 受影响 Node/浏览器脚本、相关集成与必要平台专项；UI保留桌面/手机及错误检查。共享代码按调用和行为影响扩围，不仅按目录或文件名判断 |
| Pi/主要依赖升级、广泛架构或协议变化、无法界定的跨模块影响 | 在受影响平台运行相应全量 Node、浏览器及相关原生/手动专项；仅某平台变化不自动触发其他平台全量 |
| 安装、打包集合、原生组件、权限、路径、持久化或迁移变化 | 补对应平台的安装/升级/正常停机/原路径恢复及原生语义检查；范围不清时扩大验证 |

复用必须能说明：基线提交/归档、实际执行的命令与结果，以及变化为什么不影响该证据。核对相关实现、锁定依赖、测试/夹具/运行器和必要的 Node/浏览器/配置条件；只说“产品代码没改”不够，也不要求为所有无关文件另建一套证明框架。最终归档仍核对清单与字节，包含所有变更；新包做必要的隔离安装/启动检查。安装算法、依赖和运行内容均未变时，可引用既有升级/恢复证据，说明仅测试或文档的包差异。公开发布前刷新覆盖实际依赖图的生产审计；相同依赖图不按候选轮次机械重复。

失败、未知退出或未解释的间歇失败不能作为通过证据。先保存现场、定位和定向验证，再集中处理改动；不得每修一个测试就再开三平台全量。测试修正不能删断言、放宽预算或反复重跑到绿；一次后来通过不能抹掉原失败。相关缺项或真实缺陷仍阻断发布，不能通过改规则清零。

## 执行成本与止损

- 开始前用一份简短记录列出要跑、复用和待确认的项。默认一个 Agent 负责；只有明确授权且有独立工作可做时委派，不为读状态或重复摘要启动审查 Agent。
- 正常阶段由脚本落盘结果；Agent只读状态摘要与失败相关日志，不反复载入完整历史。已有标准命令能完成的事，不为每轮候选重写编排、监控或验收框架。
- 先定向修复再考虑扩大。一次合理的定向验证仍不能解释失败，或再次出现同类失败时，先报告证据缺口、已耗时和下一步预算；未经重新评估不滚动新候选/全量。扩大范围要说明哪些证据失效，不能只说“更稳妥”。
- 高风险改动可安排一次有明确范围的独立审查；测试等待、文案或记录更新默认不反复委派审查。保持单次执行、隔离、凭据保护和真实退出核验，不以省成本削弱这些边界。

## 候选包

1. 从明确的源码提交准备候选，核对 Git 跟踪清单与未提交改动，冻结随包文档，列清本次执行与复用范围。源码阶段先做受影响专项和必要集成、集中处理已知失败；需要的全量安排一次，不在同一环境的源码和包内机械执行两轮。记录源码提交、实际运行版本和候选之间的差异。
2. 运行npm run pack:release（开发快照仍用pack:trial）。相同版本包存在时拒绝覆盖；冻结包变化按影响补验并记录复用关系，已公开版本不能悄悄替换。`scripts/source-files.cjs` 的发行集合与 docs/public-files.json 决定内容；LICENSE、第三方声明和原生manifest随包；AGENTS.local.md、docs/local、身份、媒体和备份禁止纳入。构建前强制核对档案记忆 bundle 存在且与审查哈希一致，保证跳过安装脚本的旧版网页更新器仍能使用新包。构建后核对manifest/hash，不能仅检查.gitignore。
3. 从该包在独立目录执行 `node scripts/install.cjs`（旧归档没有此脚本时使用 `npm ci`），不继承维护者的node_modules、Provider环境或Pi身份；完成宣称支持平台的浏览器、安装、更新和恢复回归。开发专项、源码预检和冻结归档验收是不同层；最终结果必须证明准确包内运行。
4. 更新公开平台范围与CHANGELOG，将本次结果及有效复用关系绑定到实际发布包SHA256。后续改动按上节判定失效范围，不因候选编号增加就重跑全部。
5. 准备下载包、SHA256、版本说明、安装/恢复步骤与已知限制。发布仓库/渠道和外部上传作为独立明确操作。
6. 公开发布后，在主分支把版本说明、CHANGELOG 版本标题、文档目录的“当前正式版”和[平台验证范围](../RELEASE_INSTALL_VALIDATION.md)改为已发布状态，写入最终包 SHA256；标签内的候选措辞保持不变，以 Release 页面为准。

根目录 README（英文）与 README.zh-CN.md 面向首次访问者，介绍功能、平台和快速开始，通过 Release 徽章和链接指向最新版本；不要在其中写入具体版本号、测试数量、验收平台版本或包 SHA256，这些只放在版本说明、平台验证范围和 Release 附件中。首页截图和动图保存在仓库的 `docs/assets/readme/`，README 用 GitHub 绝对地址引用，不进入发行包；界面有明显变化时，用独立身份和合成数据重新截取中英文两套。

Git忽略不删除已经跟踪的内容或历史。新仓库初始化时检查暂存清单；如果别处已有仓库，先检查git ls-files和历史是否包含私有文件，不能据ignore宣称历史已经清理。

## 可复跑的隔离验收

使用独立Node22、系统Bash/rg/tar，以及自行安装的Playwright 1.58.2和对应平台Chrome/Chromium。Playwright不属于用户安装的必要依赖。下列参数都替换为自己已核对的绝对路径与哈希，output目录必须尚不存在：

```sh
node test/release/acceptance.cjs --archive /path/pivane-VERSION.tar.gz --sha256 SHA256_VALUE --browser /path/to/chrome --playwright /path/to/playwright --output /path/to/new-report-directory
```

Windows用自己的node.exe和带引号的Windows路径传递相同参数。脚本可选的--previous-archive和--previous-sha256用于真正的旧包升级验收；公开发布已有前一正式版时必须传入已核对的旧包，不能用省略参数的同包重开替代。确无前版的首次发布记录不适用原因；没有旧包时结果只表示同包重开与恢复，不称跨版本升级。不要将来自未知来源的压缩包交给此脚本。

脚本新建系统临时目录，使用随机run ID、哨兵、独立Agent/媒体/项目/预约路径和最小环境，从归档解包后执行统一安装入口（旧归档回退 `npm ci`）；npm配置也独立。固定loopback8089只用于合成Provider，占用时失败，不结束已有进程；Web使用独立随机loopback端口。仅该标记临时目录允许测试脚本运行，普通安装不调用此入口。当前测试守卫不再按历史 `pi-workspace` 目录名豁免哨兵检查；复跑验收应使用上述入口新建隔离目录，旧发行归档内容保持不变。

脚本验收包含npm test、check、check:docs、audit、目标系统打包、桌面/手机安装与刷新、真实Pi RPC/Shell/历史/侧聊/导入导出，以及停机更新、原路径逐文件恢复、正数用量、搜索和媒体解码。16×16一秒黑色视频为随包合成fixture，不调用媒体生成服务。服务器通过测试父进程的私有IPC触发原SIGINT关闭逻辑，没有新增HTTP退出接口。RC各阶段必须退出码0；旧包的已知signal-exit问题只在结束全部worker后单独记录，不计作RC正常停机或放宽新包断言。

`acceptance.cjs` **不运行完整 `npm run test:browser`**，且其核心检查没有定向选择开关；需要整套核心验收时才调用，不能为了一个局部补验机械重跑该入口。需要建立全量浏览器基线时，在隔离解包/锁定安装目录显式跑完整自动浏览器及相关手动专项。定向补验使用现有测试入口并绑定执行内容、环境和对应归档；按上节记录复用。不能把 acceptance 成功或语法检查冒充浏览器全量；各宣称平台都须有覆盖所需行为的本次或有效复用证据，真实缺项仍阻断发布。

成功后删除合成身份，保留指定output中的日志与result.json；失败保留隔离目录供诊断。不会更新任何用户实例，不设置开机启动或端口转发。完整本地日志可能包含测试路径，公开时只提取平台、版本、检查结果和包SHA256，形成同名validation.json；不得为了把验收哈希写回包内而产生循环重打包。

## 兼容与恢复

新版本使用固定数据绝对路径、独立代码目录和锁定依赖。备份前暂停预约、处理未保存草稿、等待所有冲突操作结束并停机；恢复比对字节应在启动Pi前完成，启动后再核对会话ID和语义。不要文本改写JSONL路径冒充完整树迁移。

原生组件更新要绑定源码/binary/manifest并在目标系统验证。编译了某架构不等于其真机通过；平台范围以[验证说明](../RELEASE_INSTALL_VALIDATION.md)为准。真正使用供应商账户的请求与合成服务验收分开，不自动调用付费生成。

源码Agent的更多约束见[AGENTS.md](../../AGENTS.md)。
