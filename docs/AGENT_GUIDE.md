# 帮助用户操作 Pivane 的 Agent 指南

本文件面向用户自己的Agent：安装、配置、升级、备份与排障。只有用户明确要求修改Pivane源码时，才转读根目录AGENTS.md和开发文档。

## 先确认操作对象

读取用户指定的代码目录、启动方式和运行配置。只提取所需的非秘密路径/变量名，不打印.env、auth.json、Key、Cookie或私钥。确认操作系统、Node版本、当前URL、PI_CODING_AGENT_DIR、PI_MEDIA_DATA_DIR、PI_WEB_DEFERRED_FILE、PI_PROJECT_ROOTS；不要根据安装目录名称推断数据目录。

用户可能已有 Pi CLI。普通个人安装沿用该用户实际 Pi 身份，优先核对 CLI 启动环境的 `PI_CODING_AGENT_DIR`；无覆盖时使用 Pi 的平台默认主目录。按[已有 Pi 接入](PI_CLI.md)取得真实路径，不自动新建空身份或复制认证。没有已有身份时在原生默认位置初始化；只有用户要求独立实例或隔离验收时才另建身份。Pivane 媒体和预约使用实例独立绝对路径，不替换系统 Node。PI_MEDIA_PROFILE=clean 只改变媒体配置加载，不会清除进程环境中的凭据，也不是工具沙箱。

## 普通安装的最短交付流程

用户只给 GitHub 仓库并要求部署时，先读 README 和本指南，再读对应平台安装文档。默认使用 Release 包和校验文件；用户明确要求源码 checkout 时记录 commit，仍按安装流程操作，源码安装不自动变成开发验收。

1. 核对实际执行的 Node/npm、rg、目标端口及目录权限。版本管理器中可下载的版本不等于已安装；切换后读取 `node --version` 和 `node -p 'process.execPath'`。切换或前置检查失败立即停止当前安装命令链，不继续 `npm ci`。推荐 Node22.x，其他主版本未在普通安装基线验收，不据此断言全部不兼容。
2. 复用已核对的 Pi 身份，告知实际路径和共享范围；媒体与预约仍使用此实例的独立数据目录。不要把安装 Agent 继承的身份变量误当成目标用户的 CLI 配置。普通安装默认开放电脑上系统用户可访问的目录：Linux/macOS 使用 `PI_PROJECT_ROOTS=/`，Windows 使用各盘符根目录，按平台文档生成配置。无需额外询问最小范围，不自行限制为 Documents、仓库或 demo 目录；只有用户明确要求缩小时才设置较窄范围。交付实际范围，目录白名单不是工具沙箱。
3. 在所选 Node 下执行一次 `npm ci`，写入绝对路径配置，按平台文档安装后台常驻服务。安装失败才针对原因修复，成功后不重复安装依赖。
4. 只读检查访问状态、Pi 状态和网页可打开，即可交付“服务已启动”；列出 URL、版本、实际 Pi 身份、媒体/预约路径、项目范围、启动/停止方式。复用身份时核对已配置供应商和可用模型；为空先排查目录和启动环境，不直接要求用户重新登录。认证与真实请求的验证状态单独说明。

普通安装不要求 `npm test`、语法/文档全量检查、桌面/手机截图回归、打包或恢复演练。用户要求安装体验测试时，分别记录首次界面可用耗时与后续验收耗时；依赖下载、启动、排障分开计时，不把总会话时长当作产品安装耗时。

后台常驻是普通安装的默认交付，前台 `npm start` 仅用于用户明确选择的试用或排障。配置完成后运行 `node scripts/install-service.cjs`，默认给 macOS/Windows 创建桌面浏览器入口；不再要求用户保留终端窗口。入口仅打开网址，不启动重复实例。Linux 用户服务默认登录后启动，服务器应由管理员为实际用户配置 `loginctl enable-linger <用户>` 并验证注销后可达；没有用户 systemd 时，按同一用户、绝对 Node/PATH/工作目录配置系统服务，不悄悄回退为 nohup。macOS LaunchAgent 和 Windows 计划任务登录后启动，关机、睡眠或注销期间不能保证远程访问。

已有常驻部署保留原服务，不重复安装或替换。固定 Node 绝对路径、PATH、HOME 和工作目录，保留实际 Pi 身份与认证依赖。依赖环境变量的凭据和代理应私密写入实例配置，不依赖安装 Agent 临时 shell。检查 HTTP 就绪、实际版本和身份、服务归属、关闭安装终端后可达、日志与停止/卸载方式；有条件时验证重新登录/重启。不能只凭进程存在或服务管理器 running 宣称交付成功。跨平台模板检查不等于目标系统实机验收，必须报告实际验证范围。

## 安装与诊断

- 使用用户取得的候选包和校验值，按[安装指南](INSTALL_RECOVERY.md)解包并运行npm ci；不要把本机工作目录整体复制给用户。
- Node22.x及平台前提见[Linux通用步骤](INSTALL_RECOVERY.md)、[macOS](MACOS.md)、[Windows](WINDOWS.md)。原生组件必须保留源码/二进制/manifest，不删除校验绕过错误。
- 先读取`/api/access/status`判断访问验证，已认证后读取`/api/pi/status`和必要的activity。401/403、未知字段或连接失败都不表示实例空闲。
- 模型和参数从实例实际目录/schema获取，不硬编码个人Provider或静默换模型。Key通过网页原生认证或用户授权的公开认证接口保存，不手写auth.json。
- 普通健康检查不发送模型消息。模型测试和媒体生成可能收费，需要用户对相应操作的授权；不重放失败/结果不确定的请求。

## 升级、停机和恢复

先完成可审阅的包校验、路径核对与备份准备；已有用户授权覆盖的操作可继续，无需重复征求同一许可。

当前源码提供[Pi受管更新、备份与重启](UPDATES.md)。先读 `/api/pi/settings/updates/maintenance` 核对启动器能力；版本检查不表示已安装，也不授权执行。用户授权维护后仍须按 review/execute 的确认票据执行，不提交任意版本、URL或命令，不重放失败/不确定请求。受管备份不含项目源码及外置链接内容，不能替代下述完整部署备份。不得通过此入口停止承载当前操作会话的服务。

1. 核对主Agent、手动Shell、等待确认、侧聊、预约、媒体、配置操作及导入导出状态。不能停掉承载当前操作会话的服务；需要从独立管理通道安排停机。
2. 提醒保留浏览器未发送草稿/附件，暂停预约，等任务结束后按当前启动方式停机。
3. 整批保存Pi身份/会话、媒体历史与文件、项目、启动配置和原生目录权限。备份含凭据，不上传到公共仓库或对话。
4. 在新代码目录安装锁定依赖，使用原来的数据绝对路径启动。按只读状态核对项目、会话、配置及文件；不要创建新空身份覆盖旧身份来掩盖错误。
5. 恢复优先回原路径。不要正则替换JSONL里的cwd来声称完成跨路径树迁移。恢复预约后逐项核对时间与状态，不自动重发过期或投递不确定的消息。

停止和历史导航不能撤销已经执行的工具或外部请求。Windows的Ctrl+C与强制结束进程也不是等价操作。

## 排障与交付

依据用户授权进行可逆修复，优先只读收集必要信息。报告发生了什么、修改了哪些文件、如何验证及仍然不确定的范围。分享日志前移除凭据、私人正文、账户标识和不必要的机器地址。

Pivane保留PI_*变量、pi5-*数据文件、API路径和浏览器存储键，以兼容已有安装。用户不需要为改名重命名服务或数据目录。HTTP/WS契约见[API](API.md)，常见故障见[运维](OPERATIONS.md)，已验证系统范围见[平台说明](RELEASE_INSTALL_VALIDATION.md)。
