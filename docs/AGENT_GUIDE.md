# 帮助用户操作 Pivane 的 Agent 指南

本文件面向用户自己的Agent：安装、配置、升级、备份与排障。只有用户明确要求修改Pivane源码时，才转读根目录AGENTS.md和开发文档。

## 先确认操作对象

读取用户指定的代码目录、启动方式和运行配置。只提取所需的非秘密路径/变量名，不打印.env、auth.json、Key、Cookie或私钥。确认操作系统、Node版本、当前URL、PI_CODING_AGENT_DIR、PI_MEDIA_DATA_DIR、PI_WEB_DEFERRED_FILE、PI_PROJECT_ROOTS；不要根据安装目录名称推断数据目录。

用户可能已有Pi CLI或其他Pivane实例。新安装使用独立、绝对路径的数据目录和项目根；不替换系统Node、不复制其他实例身份。PI_MEDIA_PROFILE=clean只改变媒体配置加载，不会清除进程环境中的凭据，也不是工具沙箱。

## 安装与诊断

- 使用用户取得的候选包和校验值，按[安装指南](INSTALL_RECOVERY.md)解包并运行npm ci；不要把本机工作目录整体复制给用户。
- Node22.x及平台前提见[Linux通用步骤](INSTALL_RECOVERY.md)、[macOS](MACOS.md)、[Windows](WINDOWS.md)。原生组件必须保留源码/二进制/manifest，不删除校验绕过错误。
- 先读取`/api/access/status`判断访问验证，已认证后读取`/api/pi/status`和必要的activity。401/403、未知字段或连接失败都不表示实例空闲。
- 模型和参数从实例实际目录/schema获取，不硬编码个人Provider或静默换模型。Key通过网页原生认证或用户授权的公开认证接口保存，不手写auth.json。
- 普通健康检查不发送模型消息。模型测试和媒体生成可能收费，需要用户对相应操作的授权；不重放失败/结果不确定的请求。

## 升级、停机和恢复

先完成可审阅的包校验、路径核对与备份准备；已有用户授权覆盖的操作可继续，无需重复征求同一许可。

1. 核对主Agent、手动Shell、等待确认、侧聊、预约、媒体、配置操作及导入导出状态。不能停掉承载当前操作会话的服务；需要从独立管理通道安排停机。
2. 提醒保留浏览器未发送草稿/附件，暂停预约，等任务结束后按当前启动方式停机。
3. 整批保存Pi身份/会话、媒体历史与文件、项目、启动配置和原生目录权限。备份含凭据，不上传到公共仓库或对话。
4. 在新代码目录安装锁定依赖，使用原来的数据绝对路径启动。按只读状态核对项目、会话、配置及文件；不要创建新空身份覆盖旧身份来掩盖错误。
5. 恢复优先回原路径。不要正则替换JSONL里的cwd来声称完成跨路径树迁移。恢复预约后逐项核对时间与状态，不自动重发过期或投递不确定的消息。

停止和历史导航不能撤销已经执行的工具或外部请求。Windows的Ctrl+C与强制结束进程也不是等价操作。

## 排障与交付

依据用户授权进行可逆修复，优先只读收集必要信息。报告发生了什么、修改了哪些文件、如何验证及仍然不确定的范围。分享日志前移除凭据、私人正文、账户标识和不必要的机器地址。

Pivane保留PI_*变量、pi5-*数据文件、API路径和浏览器存储键，以兼容已有安装。用户不需要为改名重命名服务或数据目录。HTTP/WS契约见[API](API.md)，常见故障见[运维](OPERATIONS.md)，已验证系统范围见[平台说明](RELEASE_INSTALL_VALIDATION.md)。
