# 版本与更新

“设置 → 版本与更新”展示 Pivane 和当前实际运行的 Pi Coding Agent 的**当前版本、最新版本**及状态。首次打开且没有缓存时自动检查一次，也可点击“检查更新”；部署端查询 GitHub Releases 和 npm，结果缓存 5 分钟。Pivane 默认从公开 Release 中选取 SemVer 最高版本，**包含预发布版**，页面不再区分渠道。网络不可达时会分别显示检查失败，不推断已经是最新。

Pi 的自动检查默认开启：页面可见时最多每 24 小时查询一次 npm 正式版；发现新版可在设置入口看到提示，空闲时的轻量提醒可打开版本页、延后或忽略当前版本。检查和提醒都**不会下载或安装**。工作台的 Pi 依赖与机器上全局 Pi CLI、Packages 扩展是不同安装。

## 请独立 Agent 协助

展开“交给独立 Agent 协助更新”，复制提示词交给**部署机器上独立运行**的 Agent，或交给管理员。提示词要求先只读核对运行版本、源码、官方发布、兼容性及锁定依赖，提出备份与回退计划，等用户明确确认后再执行；更新前结束任务与外部共用身份的写入，停机备份并核对下载包及数据。

不要让运行在待更新 Pivane 实例中的 Agent 停止或重启承载它当前会话的服务。版本卡片只提供官方发布页面链接；网页不再提供安装、仅备份、重启、下载发布包或下载校验文件按钮。实际安装、备份与恢复可参考[安装与恢复](INSTALL_RECOVERY.md)、[macOS](MACOS.md)及[Windows](WINDOWS.md)；先根据部署环境和目标版本核对步骤，不盲目套用旧版本命令。

## 锁定的 Pi 适配版本

当前 1.5.0 开发源码将 Pivane 与经过适配的 **Pi 1.0.0** 绑定；1.4.0 公开归档保持原来的 Pi 0.99.1。即使 npm 出现后续 Pi，新版维护入口也不再接受独立 Pi 升级，候选安装器在变更依赖前拒绝版本不符；需要把应用、原生 MCP 和子任务适配一起升级。版本检查仍展示上游版本，不表示可直接安装。旧 `pi-mcp-adapter` 配置转换、OAuth 与工具授权边界见[原生 MCP](MCP.md)。

## 保留的兼容边界

受管启动器、维护服务端接口、私有备份和恢复脚本**暂保留兼容**，但新版设置页不调用维护票据、不显示安装命令输出，也不会自动切换运行实例。旧客户端或经授权的外部集成仍须先检查启动器能力与空闲状态，按服务端一次性 review/execute 票据执行；网络/交接结果不确定时不要重复提交。`GET /settings/updates`、`POST /settings/updates/check` 省略渠道时默认包含预发布版；显式 `stable` / `preview` 参数仍供旧客户端使用。API 参数与错误边界见 [API](API.md#版本检查与-pi-受管维护)；受管备份不包括项目源码或外置链接目标，不能替代完整部署备份。

源码、当前运行快照和公开发布包各有独立版本身份。更新前保留尚未发布的修复，停机并保存相匹配的整批备份；切换后核对版本、会话与预约，失败时不要自动重放或将“已安装”当成“已验证启动”。
