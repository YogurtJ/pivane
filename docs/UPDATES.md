# 版本与更新

设置 → **版本与更新**分别显示 Pivane、当前运行的 Pi Coding Agent 和发布包原配 Pi 的版本。当前源码提供 Pi 的受管更新、停机备份和实例重启；Pivane 应用本身仍按发布包手动更新。已发布的旧 RC 资产不会随源码修改而替换。

## 网页触发与结果反馈

在设置中点击“更新 Pi”，核对确认窗口后，由服务器执行更新。页面下方的“更新命令输出”显示实际安装命令、stdout/stderr、退出码及最终 Pi 版本；成功后版本卡片自动刷新，不刷新整页或清空草稿。命令失败会保留已返回的输出，不用成功文案替代错误。

这里更新的是 Pivane 实际使用的 Pi。上游 `pi update` 的自更新分支要求全局包管理器或上游受管安装，明确拒绝普通项目的本地依赖。因此本地 Pivane 使用等价的精确版本 npm 更新及兼容检查，网页显示实际的 npm 命令，不冒称执行了可用的全局 `pi update`。

当前源码的 `node server.js` 和 `npm start` 都会自动接入独立启动器。已有服务无需更改启动命令、运行用户或数据路径；按原方式加载新版后端后即可在网页使用。启动器负责让安装、停机备份和重连结果回到页面。不要从受管快照子目录另启服务。前台运行保持窗口打开，Ctrl+C 会统一清理启动器、服务和 RPC 进程。

运行用户需要能写入原安装目录，并有足够空间保留新的依赖、备份和失败现场。每个安装目录只供一个实例使用。Pi 自动更新支持 Node **22.x 或 24.x**、默认本地 Pi 安装，以及 npm registry 的 HTTPS 访问。配置了 `PI_WEB_CLI` 或 `PI_PACKAGE_DIR` 的自定义运行环境不提供 Pi 自动安装。

只读安装或源码开发可显式使用 `npm run start:direct`，等同于 `node server.js --direct`，此时不提供受管更新。不要用开发入口绕过未完成的数据恢复。旧进程只更新静态文件不会自动加载新后端能力。

## 网页操作

| 操作 | 实际行为 |
|---|---|
| 检查更新 | 查询 GitHub/npm，显示可用版本；不安装 |
| 更新 Pi | 核对 npm 最新正式版，在新目录安装精确版本并验证，暂停预约、停机备份，再切换并启动 |
| 仅备份 | 暂停预约、停机备份，再启动同一版本；备份期间会断开连接 |
| 重启实例 | 暂停预约，关闭当前服务及其 RPC 进程，再启动当前选定版本；不额外创建数据备份 |

点击操作后先核对确认窗口，再确认已保存草稿、附件和临时对话，并已停止使用同一数据的外部 Pi CLI 和其他写入进程。服务器会重新检查本实例的主任务、Shell、侧聊、临时会话、队列、配置、标题生成、导入导出、媒体和正在处理的请求。仍有活动时拒绝操作，不强行停止任务。

执行接受后，实例暂时拒绝新的普通 API 和 WebSocket 操作，维护状态仍可查询。页面显示安装、验证、停机、备份和启动状态；服务退出期间会显示等待重连。关闭设置、断网或切换设备不会取消已经提交的维护操作，也不会自动重新提交。所有预约保持暂停，核对版本、会话和媒体后再逐项恢复。

启动器只能管理本实例创建的进程，不能证明外部 CLI、外置脚本或远端任务已停止。用户确认的外部写入停止条件不能用 HTTP 空闲状态替代。

输出按完整行处理，去除终端控制码并隐藏已知环境凭据、认证/Cookie 字段及 URL 中的凭据。单行超过 16384 个字符时省略，页面保留最近 32768 个字符并提示截断；stdout/stderr 在命令退出后先排空，再报告退出码。日志不解析成 HTML，也不进入聊天记录。进程运行时经 IPC 回传，阶段变化和结束时随最近操作持久化；重连可读取已保留的输出。

## Pi 更新方式与兼容范围

此功能达到工作台内更新 Pi 的效果，但不执行全局 `pi update`。Pivane 同时使用 Pi CLI、SDK 和配套官方包；更新时同步固定 `pi-coding-agent`、`pi-ai`、`pi-server` 及已有 Pi 配套 overrides 的版本，在独立目录生成新的 lockfile 并安装依赖。

安装使用官方 npm registry 和 `--ignore-scripts`，不带入模型 Key、工作台 Token、用户 npm 认证或 `NODE_OPTIONS`。npm 的用户/全局配置和缓存放在本次私有安装目录。安装过程可能需要数分钟，网络失败后不自动重试。

安装兼容检查使用独立空身份、关闭启动联网和遥测，核对实际安装版本、lockfile、SDK、旧格式合成会话，以及 Pivane 唯一 worker 的 RPC 启动、读取和原生命名。检查不使用真实凭据或用户会话，不调用聊天模型。第三方扩展、真实供应商认证和所有模型组合仍需更新后核对；不能将基础兼容检查当作全平台、全供应商验收。

当前公开包原配 Pi 版本仍单独显示。RC4 将应用版本与依赖绑定为 Pi `0.86.0`；RC3 的原配 Pi 版本仍作为历史包元数据保留，不会因源码更新而改写。受管更新后的 `managedPi=true` 表示使用单独安装的 Pi 快照；全局 Pi CLI 与 Packages 扩展更新继续独立于工作台内核。

## 安装目录与失败处理

原安装目录下的 `.pivane-runtime/` 保存：

- `releases/<id>/`：当前 Pivane 代码的安装快照、精确依赖与完整 lockfile；原目录的 package/lock/node_modules 保留。
- `backups/<id>/`：停机数据备份及原安装元数据。
- `state.json`：当前/前一版本指针与最近维护操作的阶段；不保存聊天正文或凭据内容。

启动器仍从原安装目录运行，Pi 身份、项目和媒体路径沿用原实例。受管快照中的 Pivane 源码不会随原源码目录的后续编辑自动改变。更新 Pivane 本身时，使用新的正式发布目录并沿用原数据配置；源码开发使用独立实例与 `start:direct`。

准备或安装失败时保留当前安装。停机之后发生失败，会在确认相关进程退出后尝试用原版本启动，操作仍标记失败；这不等于已经恢复用户数据。无法恢复启动时需在部署端检查启动器输出与状态文件，必要时按下节恢复匹配的数据备份。

重启后遇到未完成的维护记录会标记中断，不自动继续安装、重放请求或恢复预约。安装/验证超时会请求终止子进程，但仍等待实际退出；超时本身不会解除互斥。服务正常退出前会等待全部已登记的 RPC 进程，包括正在关闭的 worker，SIGKILL 发出后也需确认退出。

旧依赖和备份不自动删除。不要删除正在使用的版本、前一版本或需要恢复的备份。它们同时由 Git ignore、发行允许清单、网页文件预览和文件搜索策略排除；Agent 工具仍按系统用户权限运行，这不是工具沙箱。

## 备份内容与恢复

备份包含 Pi Agent 目录、显式外置的原生会话目录、预约文件、媒体配置目录、原安装的 `.env`，以及媒体历史、prompts 和 images/videos/audio 文件。重叠目录去重；不包含项目源码、目录外的 Package source、符号链接目标、系统钥匙串或远端服务数据。项目源码仍需按[安装与恢复](INSTALL_RECOVERY.md)单独备份。

备份逐文件通过内核描述符核对路径、完整身份、类型、预算和前后变化，流式复制并计算 SHA-256。上限为 **50 GiB、100000 个文件/目录/链接条目**；超限、特殊文件或复制期间变化会失败，不报告完整备份。数据根不能包含维护存储目录。POSIX 备份目录为 0700、文件为 0600；Windows 使用现有受保护 DACL 组件。

备份采用 `manifest.json` 描述原路径和文件哈希、`files/` 保存原始字节，符号链接仅记录目标。`installation.json` 保存版本指针和 package/lock；`complete.json` 校验清单和安装元数据。它不是加密归档或完整文件系统镜像，不保留时间戳、扩展属性或硬链接关系，应将私有备份另存到自己的安全存储。

在**原安装目录**验证某次备份，ID 是备份目录名：

```bash
node scripts/restore-managed-backup.cjs <backup-id>
```

验证不会恢复数据。真正恢复前，停止启动器、所有使用相同身份的 CLI 和其他写入进程，保留当前数据并确认目标备份对应的旧版本目录仍在。然后执行：

```bash
node scripts/restore-managed-backup.cjs <backup-id> --apply-when-stopped
```

恢复器先校验哈希与匹配的保留安装，并对当前数据再做一次安全快照，然后恢复原绝对路径的文件、移除所选范围内更新后新增的文件，并切回对应安装。当前状态会先标记需要恢复；中途失败或断电时，正常启动器拒绝带着未完成状态启动，应完成恢复后再启动。它不是跨目录迁移器，不改写原生 JSONL 的项目路径。恢复后核对数据和预约，再 `npm start`。

POSIX 恢复保留文件所有者的读/写/执行权限并移除组/其他用户权限；Windows 保留私密 DACL。Windows 备份含符号链接时，自动恢复在写入前拒绝，需要使用原生工具手动恢复这些链接。外部副作用不会随恢复撤销。

## 自动检查与提醒

“自动检查 Pi 更新”默认开启，可在设置 → 版本与更新关闭；选择由本实例的所有设备共用。页面打开完成约 5 秒后、回到可见页面时，以及保持可见期间，会核对是否到期。距离上次成功检查达到 24 小时才查询一次 npm 正式版信息；不会后台定时安装、下载依赖或发送模型请求。无人使用页面时不检查。Pivane 的正式版/预发布渠道仍由手动检查独立控制。

同一实例的多个标签页和设备共用检查结果与进行中的请求。成功时间、版本和提醒选择写入实例偏好，服务重启后保留。失败不弹出错误，按 1、2、4、8、16、24 小时退避；设置中的“检查更新”仍可主动查询，成功结果也刷新自动检查的 24 小时期限。

发现高于当前版本的 Pi 后，设置入口显示小圆点；任务、Shell、侧聊、媒体及配置操作结束后，才尝试显示轻量提醒。同一版本由服务端协调，仅一处页面领取一次提醒。关闭后保留圆点；“3 天后提醒”到期后可再次提示；“忽略此版本”隐藏该版本提醒与圆点，下一版本仍会提示。关闭自动检查时隐藏提醒与圆点，不取消已经发出的只读查询，也不改变手动检查和已提交的维护任务。

“查看并更新”直接打开现有维护确认窗口。服务端重新核对当前可用正式版与空闲条件，用户确认保存草稿、停止外部写入后才执行；发现新版、领取提醒或打开窗口都不代表安装授权。关闭/隐藏页面与切换身份后的迟到响应不会重新弹出确认或提交更新。

## 版本查询与网络

版本快照读取本地信息和缓存。点击“检查更新”查询 GitHub Releases 与 npm，成功/失败均缓存 5 分钟，两来源独立显示结果；自动检查仅查询 npm 正式版并使用上述 24 小时期限。Pivane 正式版渠道排除预发布；包含预发布版渠道从最近 100 个公开 Release 中按 SemVer 选择最高版本，例如 rc.10 高于 rc.2。Pi 使用 npm `latest` 的正式版本，维护确认会重新核对它并绑定目标版本。

查询固定 HTTPS 来源：`api.github.com/repos/YogurtJ/pivane/releases?per_page=100` 与 `registry.npmjs.org/@earendil-works%2fpi-coding-agent/latest`。每来源最多 12 秒、2 MiB，拒绝重定向，不转发浏览器或模型凭据。支持服务器现有 `https_proxy`/`HTTPS_PROXY`、`http_proxy`/`HTTP_PROXY` 及 `no_proxy`/`NO_PROXY`；不改写网络配置。

官方下载链接仍由浏览器处理，不表示已保存到部署端或已校验。Pivane 应用发布包的手动更新见[安装与恢复](INSTALL_RECOVERY.md)、[macOS](MACOS.md)、[Windows](WINDOWS.md)。

## API 与执行边界

全部接口沿用工作台身份、Origin 校验与 `Cache-Control: no-store`：

| 方法 | 路径（前缀 `/api/pi/settings/updates`） | 内容 |
|---|---|---|
| GET | 根路径，可选 `?channel=stable或preview` | 当前版本、渠道及缓存，不联网 |
| POST | `/check` | JSON `{channel?}`；显式查询或复用缓存 |
| POST | `/automatic` | 空 JSON `{}`；按持久期限静默查询 Pi 正式版或复用结果，不执行维护 |
| GET | `/notifications` | 自动检查开关、版本、上次成功/下次检查毫秒时间、available/eligible/idle |
| POST | `/notifications` | `{enabled:boolean}` 或 `{action:"claim"或"snooze"或"ignore",version}`；修改开关或当前版本提醒 |
| GET | `/maintenance` | 维护能力、当前版本指针、进程代次、busy、最近操作及备份摘要 |
| POST | `/review` | JSON `{action:"update"或"backup"或"restart"}`；核对条件，返回 10 分钟确认票据 |
| POST | `/execute` | JSON `{ticket,confirmed:true,draftsSaved:true,externalWritersStopped:true}`；复核空闲条件，暂停预约并提交一次操作，接受返回 202 |

提醒的 `claim` 在同一进程内同步判断与保存，只有符合条件且空闲的调用返回 `claimed:true`；其他调用返回 false，不重复显示。同版本“稍后提醒”保存 3 天期限；忽略仅匹配所选版本。过期版本动作返回 409，未知字段和不支持的动作返回 400，存储/服务不可用为 503，错误不返回原始配置或网络凭据。实例偏好 `piUpdateNotifications` 只包含版本元数据、检查期限和提醒选择，不保存聊天信息；原子读改写保留无关偏好字段。

确认票据绑定进程代次、动作和服务端选择的 Pi 精确版本。执行不接受版本覆盖、URL、命令或目标路径；票据使用一次即失效，重启不恢复票据。忙碌、过期和重复执行返回 409，格式错误为 400，不支持或读取/交接失败为 503。交接不确定时保持维护状态，不将失败响应解释为没有执行。

版本快照包含 `appVersion`、`piVersion`、`bundledPiVersion`、`dependencyMatches`、`managedPi`、`channel`、`platform`、`checkedAt`、`cacheUntil` 和 `pivane/pi` 查询结果。兼容字段 `installMode:"manual"` 继续描述 Pivane 发布包安装；Pi 维护能力以 `/maintenance` 为准。结果状态为 `unchecked/available/current/ahead/unknown/no-release/error`。`/api/pi/status.version` 仍表示实际 Pi 版本。

`GET /maintenance`的最近 `job` 可带 `output`、`outputTruncated`、`exitCode`、`fromVersion`、`installedVersion`。`output`是脱敏后的命令日志尾部；无法取得进程退出码时为 null，不能用 0 代替未知。`installedVersion`只在完成安装验证和服务启动后设置。前端只读轮询不会重放执行请求。

启动器和服务用私有 IPC 通道与启动 nonce 通信，操作在 await 前预占互斥。维护期间普通 API/WS 不接受新工作，预约调度暂停；HTTP 连接断开不代表后台处理已经停止。状态读取不执行新任务，网页迟到响应不能覆盖新请求或重复安装。

## 验证范围

Node 测试覆盖票据、互斥、路径/身份、预算、哈希、文件变化、备份、恢复、版本固定、安装失败、实际退出和重复信号。真实隔离 HTTP/WS 服务验证备份及重启后的会话字节与预约暂停。中英文 Chromium 测试覆盖桌面/手机、确认勾选、取消、断连、迟到响应和子项宽度。

`test/release/pi-managed-update.cjs` 是需显式启用的隔离联网演练：在临时安装与空身份中执行真实 npm 更新，不更新用户实例。RC3 发布附件记录的是 Pi 0.85.0 → 0.85.1 演练；RC4 绑定 Pi 0.86.0，需以 RC4 的隔离安装和平台验收结果为准，不能套用旧 RC 安装验收结果。
